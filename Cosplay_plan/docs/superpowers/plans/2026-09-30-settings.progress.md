## Ruling

- **Ruling: `displayName` ว่าง = ล้างชื่อได้ (เรียก `updateProfile` ด้วย `''`)** — ในดีไซน์เขียนว่า "ชื่อว่างไม่เรียก" แต่ถ้างั้นผู้ใช้ที่มีชื่ออยู่แล้วจะลบชื่อไม่ได้เลย · เลือก "ล้างได้" เพราะ Header ตกไปใช้อีเมลอัตโนมัติเมื่อชื่อว่าง · ถ้าผิด = ผู้ใช้ลบชื่อทิ้งไม่ได้ (แก้ได้ภายหลัง)
- **Ruling: error map ใช้ key เต็ม `auth/...`** — Firebase Auth คืน code มี prefix เสมอ; Firestore ไม่มี prefix (ใน `utils/errors.ts` เป็นแบบไม่มี prefix ถูกต้องแล้ว ไม่แตะ) · **พบสาเหตุที่ Login/Register แสดงแต่ข้อความ generic**: map key เดิมไม่มี prefixจึงไม่มีวัน match
- **Ruling: แยก 3 ฟอร์มเป็น 3 component ใน `components/settings/`** — หน้าเดียวยาวเกินจะอ่านง่าย และทดสอบทีละส่วนได้ (แพตเทิร์นเดียวกับ `components/dashboard/`, `components/project/`)
- **Ruling: ปุ่ม ⚙️ อยู่ในแถบบน ไม่เพิ่มใน `NAV_ITEMS`** — แถบล่างมือถือจะแน่นเกินไป (3 → 4 รายการ) + เรื่องบัญชีไม่ใช่งานหลัก (ตามที่อนุมัติ)
- **Ruling: ไม่มีเทสต์เชิงพฤติกรรมของฟอร์ม (กดบันทึกแล้วเกิดอะไร)** — ต้องการ DOM; repo ใช้ `renderToStaticMarkup` ล้วน (ไม่มี jsdom) · logic ที่สำคัญ (ลำดับ re-auth → update, error แปลไทย) ถูกทดสอบที่ `authActions`/`authErrors` แทน · **ต้องลองด้วยมือในเบราว์เซอร์**
- **ข้อควรรู้:** แก้ไฟล์ที่มีข้อความไทยด้วย `edit` ต่อไม่ได้ (Unicode normalization ไม่ตรงกับไฟล์ → `oldString` match ไม่เจอ) ใช้ `python3` + regex แทน

## แก้ตามรีเฟรชผู้ใช้: จัดกล่องให้กลางหน้า + เว้นระยะ (2026-09-30)

- **อาการ:** กล่องทั้ง 3 ชิดขอบซ้าย (ไม่กึ่งกลาง) และ **ติดกันไม่มีช่องไฟ**
- **สาเหตุ:** `PageContainer` กว้างเต็ม (`--container-max`) แต่หน้านี้ตั้ง `maxWidth: var(--container-form)` ทีละการ์ดโดยไม่มี `margin: 0 auto` → ชิดซ้าย · และไม่มี spacing ระหว่างการ์ดเลย (`.ui-section` ไม่มี margin-bottom)
- **แก้:** ห่อทั้งหน้าด้วย wrapper เดียว `maxWidth: var(--container-form)` + `margin: 0 auto` + `display:flex; flex-direction:column; gap: var(--space-6)` · ถอด `maxWidth`/`className="ui-section"` ซ้ำออกจากการ์ด
- **⚠️ เทสต์รอบแรก "ผ่าน" ทั้งที่ยังไม่แก้ — ผิดที่!** `margin:0 auto` มาจาก `PageContainer` และ `margin-bottom:var(--space-6)` มาจาก `PageHeader` ไม่ใช่สิ่งที่แก้ · แก้ assertion ให้แม่น: ยืนยัน **string ต่อกัน** `max-width:var(--container-form);margin:0 auto` (เฉพาะ wrapper) + `gap:var(--space-6)` + นับ `max-width:var(--container-form)` ได้ **1 ครั้ง** ไม่ใช่ 3 → RED ตอนนี้ได้จริง
- **บทเรียน:** ตรวจ markup จริงก่อนเขียน assertion เสมอ (dump `style="..."` ทั้งหมด) ไม่งั้น assert จะผ่านเพราะบังเอิญ
- **Gates:** build ✓ · lint ✓ · **tests 134/134 (25 ไฟล์)** · ยืนยันโมดูลที่ dev server เสิร์ฟมี `maxWidth/margin/gap` ตรงดิสก์ · ยังไม่ commit

## บั๊กจากงานเมื่อกี้: inline style ทับ media query (ผู้ใช้เจอเอง) — 2026-09-30

- **อาการ:** มือถือยังเห็น ⚙️ + ปุ่ม "ออกจากระบบ" ซ้ำกับที่อยู่ใน dropdown
- **สาเหตุ:** ใส่ `style={{ display: 'flex' }}` เป็น **inline style** ไว้บน `.header-account-inline` → **inline style ชนะ media query เสมอ** กฎ `@media { display: none }` จึงไม่มีผล (พิสูจน์ด้วยการ dump markup: `<div class="header-account-inline" style="display:flex;...">`)
- **แก้:** ย้าย `display/align-items/gap` ไปไว้ใน CSS class (JSX ไม่มี style แล้ว) → media query คุมได้จริง
- **TDD:** เพิ่มเคสกันซ้ำ `expect(html).not.toMatch(/class="header-account-inline"[^>]*style="[^"]*display/)` → RED ก่อนแก้ ✓
- **ข้อสรุปที่ต้องจำ: ถ้าจะสลับ display ตาม breakpoint ห้ามใช้ inline style เด็ดขาด** (ซ้ำกับบทเรียนเรื่อง antd `Dropdown` ที่ `className` ไปอยู่บน overlay)
